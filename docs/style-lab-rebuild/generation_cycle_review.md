## 화면과 사용 순서

- Mobile 하단은 **프로젝트 / 생성 / 선별 / 진화 / 그림체**입니다. 설정은 상단 버튼으로 열고 프로젝트 선택은 계속 공유합니다. Desktop Sidebar에도 프로젝트 목록과 이미지 생성·진화를 구분합니다.
- 처음에는 현재 세대의 초기 후보를 만듭니다. 기본 후보 수는 평가에 필요한 10개에서 현재 Pool 수를 뺀 값이며, 1~32개로 변경할 수 있습니다. 저장한 프로젝트의 성분 개수·STR 범위·Workflow·전체 Prompt·Seed를 기존 생성 경로에 전달합니다.
- 초기 Pool을 선별한 뒤 같은 생성 버튼은 **다음 세대 후보 생성**으로 작동합니다. 이후 후보는 기존 상위 30% 부모와 Mutate·Crossover·Random을 사용하는 진화 계획입니다. 기존 세대에 독립 무작위 조합만 계속 붙이는 동작으로 대체하지 않습니다.
- 진화 탭은 진행 후보, 고정된 비교 기준 부모, 평가 완료·생존 예정·탈락 예정, 확정 결과와 세대 이력을 보여 줍니다. 카드는 그림체 탭의 기존 카드와 공통 Viewer·Thumbnail Cache를 재사용합니다. 선택·일괄 관리는 그림체 탭에서 합니다.
- 모든 Prompt 이미지와 자녀 선별이 끝나면 **세대 확정** 또는 **확정하고 다음 후보 생성**을 선택합니다. 후자는 다음 후보 수를 입력하고 확인창 하나에서 다음 생성 장수 상한까지 확인합니다.
- 확정한 세대 번호와 아직 평가 중인 다음 후보의 세대 번호를 구분합니다. 예를 들어 현재 2세대 상태에서 3세대 후보를 선별하고, 확정할 때 현재 세대가 3으로 바뀝니다.
- 선별의 Vote·Skip·Undo·성분 차이·Prompt별 세로 Scroll·하단 고정 선호 버튼은 유지합니다. 선별 완료 후 진화로 이동하거나 선별 화면에서 확정할 수 있습니다.
- 진행 생성의 취소·실패 재시도는 기존 CHS 조작을 재사용합니다. 이번 진화 전체 취소는 접힌 보조 조작이며 부모 세대의 평가 상태로 돌아갑니다. 이 취소는 실제 이미지·작업 이력을 지우는 세대 복원 기능과 다릅니다.

## 선별·확정 정책

- 기존 최소 평가 수 **10개**, 미배치 후보 완료, 상위 30% 경계 동점 해소 조건을 유지합니다. 조건을 충족하지 않으면 생성 버튼을 막고 필요한 사항을 접힌 영역에 표시합니다.
- 진화 중 부모의 비교 기준 점수는 고정합니다. 자녀를 선별하고 확정하면 살아남은 자녀가 활성 Pool에 들어오고 기존 하위 조합이 가능한 수만큼 퇴역합니다. 그림체 탭에서 활성·퇴역·취소와 점수를 계속 조회합니다.
- 확정 뒤 다음 부모 선발 경계에 동점이 생길 수 있습니다. 이 경우 **확정 자체는 완료**하고 다음 후보 생성은 추가 선별 뒤 `이어하기`로 계속합니다. 임의로 동점을 무시하거나 점수를 조작하지 않습니다.
- 사용 가능 성분·범위가 좁아 새 조합이 부족하면 실제 준비한 수만 생성하고 기존 부족 안내를 사용합니다. 같은 성분·STR 조합을 복제해 요청 수를 채우지 않습니다.
- 초기 Pool을 채우는 동안의 직접 조합 지정과 새 Prompt의 같은 조합 재생성은 기존 기능으로 유지합니다. 평가 Pool이 준비되면 일반 생성 화면은 다음 세대 후보 생성을 중심으로 표시합니다.
