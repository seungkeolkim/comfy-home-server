# 탐색 알고리즘과 여러 그림체의 보존

새 구현의 결정 기록입니다. 기존 알고리즘 설명은 [04번 문서](04_evolution_and_component_scores.md)에 있으며, 아래 보강은 아직 구현되지 않았습니다.

## 유지할 기본 구조

사용자가 이미지를 비교하고 그 선호로 다음 후보를 만드는 Interactive Evolution을 유지합니다. Mutate/Crossover/Random의 초기 비율은 기존 1:1:1을 기준으로 합니다. 알고리즘 전체 교체보다 프로젝트 격리, 생성 조건 일치, 여러 계보 보존, 같은 조합의 Prompt 재시험을 먼저 구현합니다.

이 결정은 현재 알고리즘의 성능 우위를 입증했다는 뜻은 아닙니다. 실제 평가 횟수와 생성 비용 안에서 원하는 그림체를 여러 개 확보하는지가 판단 기준입니다. 기존 산식의 재현과 새 탐색 정책의 검증을 분리하고 `algorithm_version`을 기록합니다.

## 여러 계보에 부모 기회 부여

기존의 전체 상위 30%만 부모로 선택하면 다른 매력이 있는 하위 계보가 사라질 수 있습니다. 새 설계는 전체 상위 후보와 사용자가 유지한 계보의 대표 후보를 함께 부모 Pool에 넣고, 계보별 자녀 생성 기회를 배정합니다.

- 계보는 처음에는 사용자가 구분하고 대표 후보를 지정합니다. 같은 후보의 중복 배정은 중복 생성으로 이어지지 않게 처리합니다.
- 북마크는 삭제 보호이고, 계보 대표 지정은 탐색 기회 보장입니다. UI에서 구분합니다.
- 계보 내부에서는 기존 순위 기반 부모 선택을 활용합니다. 다른 계보끼리의 Crossover는 허용 여부를 명시합니다.
- 자녀 수와 계보 수에 따라 실제 배정 수를 미리 보여줍니다. 모든 계보에 기회를 줄 예산이 부족하면 안내하고 사용자가 조정하게 합니다.
- 태그가 다르다는 이유만으로 시각적으로 다른 그림체라고 단정하지 않습니다. 자동 분류는 후속 기능입니다.

부모 기회를 배정하는 정확한 비율·최소 관측 수는 구현 전에 정책값으로 확정하고 저장합니다. 최초 기본값은 균등한 계보별 기회 배정으로 제안하되, 검증되지 않은 최적값으로 표현하지 않습니다.

## 탐색과 검증의 조건

한 평가 구간의 탐색은 같은 Prompt·Sampling Seed·Workflow 조건을 사용합니다. 최종 후보는 공통의 추가 Seed 묶음에서 검증합니다. 예를 들어 2~3개 Seed로 시작할 수 있으나 최적 개수로 확정한 값은 아닙니다. 추가 Seed 검증은 기존 계획대로 P1입니다.

Prompt를 바꿀 때는 다음 세대를 만드는 대신 [현재 조합의 Prompt 재시험](17_prompt_retests_and_reranking.md)을 P0로 제공합니다. 계보, 성분, 가중치를 바꾸는 탐색과 같은 조합의 조건 적응도를 확인하는 시험을 별도 동작으로 둡니다.

추가 채택한 [19번 기능](19_adopted_exploration_tools.md)은 탐색을 보강합니다. 모든 생성 방식에 성분·Weight 잠금을 적용하고, 분기는 같은 조건의 Snapshot에서 독립 탐색합니다. Ablation·대표 Prompt/Seed 검증은 원본 Elo와 분리하며, 비교 추천은 필수 Placement/Selection 뒤 일반 대결에 적용합니다. Genetic Algorithm과 Elo 산식 자체는 이 기능을 이유로 자동 교체하지 않습니다.

## 대안의 위치

| 방법 | 검토할 상황 | 현재 결정 |
| --- | --- | --- |
| Preference-based Bayesian Optimization | 사용할 LoRA 몇 개를 고정하고 연속 Weight를 적은 비교로 조절할 때 | 후속 실험. 큰 범주의 작가·LoRA 선택까지 즉시 대체하지 않음 |
| Quality-Diversity / MAP-Elites | 서로 다른 특성의 좋은 결과를 여러 개 보관할 때 | 계보 보존 원칙을 먼저 적용. 전체 도입에는 의미 있는 다양성 Descriptor 필요 |
| Interactive Evolution | 사용자가 비교하며 범주와 Weight 조합을 함께 탐색할 때 | 기본 방식 유지, 계보 보존과 재시험 보강 |

방법론 근거는 [BoTorch의 Pairwise Preference BO 문서](https://botorch.org/docs/tutorials/preference_bo), [MAP-Elites 원 논문](https://arxiv.org/abs/1504.04909), [Interactive Quality-Diversity 연구](https://arxiv.org/abs/2304.01642)를 참고합니다. 이 자료들이 이 프로그램의 Anima/Moss 탐색에서 특정 방법의 우위를 검증한 것은 아닙니다.

## 수락 기준

- 유지 대상으로 지정한 계보는 전체 상위 30% 밖이어도 배정된 부모 기회를 얻습니다.
- 계보 수보다 생성 예산이 작을 때 배정 누락을 숨기지 않습니다.
- 원본 알고리즘 Golden Fixture와 새 정책 Fixture를 구분합니다.
- 저장한 정책과 Random Seed로 부모 배정 근거를 확인할 수 있습니다.
- 같은 조건과 생성·비교 예산으로 확보한 서로 다른 SavedStyle 수를 측정할 수 있습니다.
