# 그림체 폐기와 CHS 생성 이력 정리

2026-11-12. 기준 Commit `2cb591a`. 사용자 피드백에 따라 그림체 폐기는 이미지와 화면 표시뿐 아니라 **현재 Elo·Placement·선별 대상과 해당 CHS 생성 요청**까지 정리합니다.

## 원인과 변경 계약

이전 조합 폐기는 모든 Prompt 파일을 삭제하고 Membership을 `deleted`로 바꾸되 CHS 요청과 작업 이력을 유지했습니다. 현재 화면의 비교 캐시와 일반 Placement의 기준 목록도 명시적으로 정리할 필요가 있었습니다. 기존 `style_usability_review.md`의 작업 이력 보존 설명은 이번 결정으로 바뀝니다.

- 단건·일괄·선별 양쪽 폐기는 같은 경로를 사용합니다. 삭제한 조합의 모든 Prompt 및 이전 실패·재시도 이미지를 기존 CHS 파일 삭제·경로 검사·Cache 무효화로 제거합니다.
- 해당 조합의 Render, Output Catalog, CHS 요청과 요청 결과를 제거합니다. 한 작업에 다른 조합이 남으면 그 요청만 유지하고 `request_count`를 갱신합니다. 요청이 모두 사라진 작업은 소유 관계·입력·분류 연결과 함께 삭제합니다. 일반 생성 작업에는 적용하지 않습니다.
- 현재 Elo, 현재 A/B, Placement의 대상·기준 목록, 경계 동점·최근 Pair에서 삭제한 조합을 제외합니다. 이전 Undo로 되살릴 수 없으며, Browser의 후보·순위 캐시에서도 응답 직후 제거합니다. 보충 가능한 보관 조합 없이 마지막 조합을 지우면 선별 화면은 빈 상태가 됩니다.
- 비교 기준을 삭제해 신규 조합 하나만 남은 경우 `placementPending`을 종료합니다. 기준점이 없어도 Placement를 반복하거나 재귀 오류를 내지 않습니다.
- 이미 `deleted` 처리한 옛 명령도 서버 시작 시 `cleanupVersion=2`로 정리합니다. 현재 조회에서도 옛 삭제 상태에 남아 있는 Elo·Pair 참조를 제거합니다. 완료한 명령의 재전송은 같은 응답을 반환합니다.
- 삭제 의도를 먼저 영속화하고, 파일 삭제 후 관계 정리는 한 DB Transaction으로 처리합니다. 파일 또는 DB 정리가 실패하면 완료로 표시하지 않으며 같은 명령의 재시도·재시작 복구를 지원합니다.
- 프로젝트·Prompt·Workflow 설정과 다른 조합의 Elo·이미지를 유지합니다. 불변 생성 Plan·Event·Checkpoint와 재생성 방지용 삭제 표시는 보존하지만, 이 표시가 비교 대상·실제 생성 요청·작업 이력으로 노출되지는 않습니다. 기존 즐겨찾기는 원본 작업과 독립적인 저장본이라는 CHS 계약을 유지합니다.
- 준비·진행 중 진화, 생성·취소 중 요청, 삭제 보호된 Job에 대한 기존 차단은 유지합니다. 새 Schema나 별도 이미지 Cache는 추가하지 않습니다.

## 2026-11-17 활성 결원 보충

활성 여부는 `style_candidate_memberships.lifecycle`에 저장합니다. `active`는 생존 조합, `retired`는 탈락 후 이미지·점수를 보관한 조합입니다. `evolving`은 진화 선별 중, `cancelled`는 취소, `deleting`·`deleted`는 폐기 중·완료 상태입니다.

기존 폐기는 활성 수만 줄이고 보관 조합을 승격하지 않았습니다. 앞으로는 폐기 직전의 **해당 프로젝트·Evaluation 활성 수**를 기준으로, 삭제로 생긴 결원을 보관 조합으로 보충합니다. 50개 같은 공통 상한을 새로 적용하지 않습니다.

- 순위는 그림체·선별에서 사용하는 `ranked_candidate_statistics`와 같은 Elo·동점 정렬을 사용합니다. 현재 생존 조합을 다시 탈락시키지 않고 보관 조합 중 다음 순위부터 승격합니다.
- 모든 Prompt가 완료됐고 Catalog와 실제 파일이 준비됐으며 평가가 완료된 `retired` 조합만 승격합니다. 같은 요청으로 폐기하는 조합, 취소·삭제 상태, 다른 프로젝트·Evaluation은 제외합니다.
- 승격은 `lifecycle`만 `active`로 바꿉니다. 기존 Elo·승패·세대·계보·이미지·즐겨찾기·CHS LoRA 등록본은 유지하고 새 이미지는 생성하지 않습니다.
- 폐기 의도와 승격을 같은 DB Transaction에 저장합니다. 승격 저장이 실패하면 파일 삭제에 들어가지 않습니다. 파일 정리 재시도·시작 시 복구·같은 요청 재전송으로 추가 승격하지 않습니다.
- 응답의 `promotedCandidateIdentifiers`는 실제 승격 목록입니다. 기존 결과 새로고침으로 그림체·선별·다음 진화 부모 선정에 반영합니다. 보관 조합이 부족하면 준비된 수만큼 보충합니다.
- 과거 완료 명령과 불변 Checkpoint를 소급 변경하거나, 이미 줄어든 과거 정원을 추정해 일괄 승격하지 않습니다. 기존 진행 중 진화·생성·삭제 보호는 유지합니다. Schema 변경은 없습니다.

이번 보완은 폐기·정리·승격·투표·진화·Pool 회귀 **48 Passed**로 검증했습니다. 추가 회귀는 실제 세대 확정 후 순위 승격, 일괄 폐기, 파일·Prompt·평가 미완료 제외, 보관 수 부족, DB Rollback과 파일 정리 재시도의 중복 승격 방지를 확인합니다. 격리 Browser는 390px·1280px에서 활성 10개 유지, 즉시 카드 교체, Elo·승패 보존, 취소·새로고침·선별 반영을 확인했고 Browser 오류는 0건입니다. 운영 조합을 시험 삼아 삭제하지 않습니다.
