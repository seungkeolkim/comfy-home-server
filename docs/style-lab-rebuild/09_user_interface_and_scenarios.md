# 프로젝트 중심 화면과 사용 시나리오

## 기본 화면 구조

2026-11-10부터 UX의 비교 기준은 localhost:8389의 Style Lab Web·Mobile입니다. 아래 화면 구조는 재검토할 제안입니다. [20번 문서](20_web_ux_fusion_multi_prompt_and_component_differences.md)의 여러 Prompt 결과 Matrix/Case 전환, 성분 차이 보기·탐색 제외를 초기 흐름에 반영하고, 비율 지정·3개 이상 원본 융합은 후순위에 별도 UI부터 구상합니다.

일반 생성과 스타일 구성은 상단의 별도 작업 공간으로 전환합니다. 아래는 기능 범위의 개요이며, 구체적인 Desktop·Mobile 메뉴 배치와 화면 목록은 [18번 문서](18_workspace_navigation_and_screen_mockups.md)를 따릅니다. [동작하는 목업](mockups/README.md)도 함께 관리합니다.

프로젝트 목록 → 프로젝트 작업실 → 선별/진화 → 보관한 그림체 순서로 구성합니다. 기존의 여러 설정 화면을 먼저 알아야 시작할 수 있는 흐름을 줄입니다.

| 화면 | 핵심 정보·행동 |
| --- | --- |
| 프로젝트 목록 | 이름, Workflow·모델, 목적, 세대, 보관 그림체 수, 최근 작업, 생성/복제/보관 |
| 프로젝트 생성 | Fresh/점수만 복제 선택, 원본 점수 출처, 등록 Workflow, Prompt Set, 후보 Catalog, 생성 규칙 |
| 프로젝트 개요 | 고정 평가 조건, 현재 단계, 남은 비교·생성, 바로 선별/다음 세대 |
| 선별 | 같은 A/B의 Prompt별 결과, 비슷함, Undo, Blind, Mobile Case·배치 전환, 성분 차이·향후 사용 제외 |
| 진화 | 부모·후보 수, 생성 진행, 남은 검증, 세대 확정과 탈락·제외 미리보기 |
| 세대 이력 | 평가 구간별 확정 Checkpoint 목록, 선택 세대로 돌아가기, 삭제 경고 |
| Prompt 재시험 | 상위 N개 선택, 새 Prompt, 원본/신규 보기, 시험 순위·Drop 취소·채택 |
| 그림체 목록 | 활성/퇴역, 순위, Memo, 보호·보관, 복수 SavedStyle |
| 성분 정보 | 작가·LoRA 점수, 새 관측 수, 가져온 Prior 표시, 범위·호환성 |
| 프로젝트 설정 | 평가 조건 보기, 새 Evaluation Revision 생성, Catalog·탐색 규칙 |
| 후순위 도구 | 수동 조합·융합·가중치 다듬기·자유 생성 |

Desktop은 왼쪽에 프로젝트 메뉴, 본문에 큰 비교 영역을 둡니다. Mobile은 상단 작업 공간 전환과 프로젝트 경로, 하단 `비교 / 조합 / Prompt 시험 / 더보기`를 사용합니다. 진화는 프로젝트 홈·비교 화면의 실행 동작으로 제공합니다. 생성 중인 다른 프로젝트를 열어도 생성 대상이 바뀌지 않습니다.

## 시나리오 A: 특정 Prompt에 맞는 새 그림체 탐색

1. 프로젝트 생성에서 `새로 시작`을 고릅니다.
2. Home에 등록된 Anima Workflow를 선택하고 모델·Node 의존성을 확인합니다.
3. Prompt/Negative, 비교용 Sampling Seed, 해상도와 Sampling 설정을 확정합니다.
4. 작가·LoRA 후보군과 수·가중치 범위를 선택합니다. 기존 Catalog를 고르는 것과 점수를 가져오는 것은 별도 선택입니다.
5. 초기 후보를 생성하고 A/B 평가합니다.
6. 다음 세대를 생성·평가·확정합니다.
7. 마음에 드는 여러 그림체를 각각 이름과 Memo를 붙여 보관합니다.
8. 선택적으로 다른 Seed 묶음에서 검증하고 안정적인 결과를 표시합니다.

## 시나리오 B: 점수만 가져와 다른 Prompt에서 시작

1. 프로젝트 생성에서 `작가·LoRA 점수만 이어받기`를 고릅니다.
2. 원본 프로젝트/Evaluation 또는 기존 Style Lab Import Snapshot을 지정합니다.
3. 가져올 성분과 점수·근거 수를 미리 봅니다. Prompt·모델 차이와 호환되지 않는 LoRA를 보여줍니다.
4. 후보0, 투표0, 세대1, 새 관측0임을 확인합니다. 원본 점수는 '가져온 점수'로 별도 표시됩니다.
5. 새 조건에서 생성·평가합니다. 원본 프로젝트의 점수는 변하지 않습니다.

## 시나리오 C: Moss로 확장

1. 먼저 Home에 Moss Workflow와 생성 Adapter를 등록합니다.
2. Style 프로젝트에서 해당 등록 항목을 선택합니다.
3. Adapter가 지원하는 성분·Seed·Negative·LoRA 설정만 표시합니다.
4. Anima 작가 점수를 가져오더라도 '다른 모델에서 가져온 Prior'임을 표시하고 호환성 검사를 별도로 수행합니다.
5. 모델에 맞는 이미지 비교를 사용합니다. Moss의 실제 출력 매체가 확정되기 전에는 영상·음성 비교를 구현 완료로 취급하지 않습니다.

## 시나리오 D: 현재 조합을 다른 Prompt에서 시험

1. 현재 세대의 그림체 목록에서 `다른 Prompt로 시험`을 선택하고 상위 N개 대상을 확인합니다.
2. 새 Prompt를 입력합니다. 작가·LoRA·Weight는 고정되고 Seed·Workflow 등 조건 유지 내역을 보여줍니다.
3. 새 이미지를 생성합니다. 원본/신규 비교 보기는 참고용이고, 투표는 시험의 새 이미지끼리 진행합니다.
4. 시험 Elo로 다시 순위를 매기고 원하지 않는 후보를 Drop합니다. 채택 전 Drop 취소가 가능합니다.
5. 시험으로 보관하거나 새 Prompt와 남은 조합을 채택합니다. 채택 화면에서 제외·미시험 후보와 진화 가능 여부를 확인합니다.
6. `12세대 / Prompt 시험 B`처럼 표시합니다. 실제 다음 진화를 시작해야 13세대가 됩니다.

상세 계약은 [17번 문서](17_prompt_retests_and_reranking.md)를 따릅니다. 시험 상태와 작성 중 Prompt는 Trial별로 분리합니다. 원본 탭의 평가나 Polling으로 시험 입력을 덮어쓰지 않습니다.

계보 보존은 그림체 목록에서 대표 후보를 지정하고 진화 화면에서 계보별 부모·자녀 배정 수를 확인하게 합니다. 북마크와 계보 대표를 별도 표시합니다.

## 오류와 기록의 노출

- Model Only의 예상 Text Encoder 미적용은 펼쳐 보는 적용 기록과 상세 Log에 남깁니다.
- 모델 Key 누락·알 수 없는 Key·Shape/Patch 오류는 계속 경고합니다.
- 조합에 여러 LoRA가 있으면 파일 전체를 실패 원인으로 지목하지 않습니다.
- 잘린 Log는 '확인 범위 일부'로 표시하고 전체 정상으로 단정하지 않습니다.
- 모바일 Toast는 최대 2개를 유지하며, 중요한 오류는 지속적인 작업 상태에서도 확인할 수 있게 합니다.
- 오래된 탭의 Vote는 409 후 새 Pair를 보여주며 사용자 선택을 새 Pair에 자동 적용하지 않습니다.

## 화면 상태 보존

세대 이력의 '이 세대로 돌아가기'는 [15번 문서의 확인창](15_generation_restore_and_deletion.md)을 한 번 표시합니다. 이후 이미지·이력·승패·Elo 변경과 이후 보관 결과가 삭제된다고 안내하고 실제 수량을 보여줍니다. 점수를 초기화하는 것이 아니라 당시 값으로 복원합니다.

프로젝트별로 Prompt 작성 중 값, 후보 필터, 선택 ID, Scroll, 비교 배치를 분리합니다. 일반 Polling과 탭 이동으로 Browser History를 늘리거나 입력값을 덮어쓰지 않습니다. 프로젝트 삭제·전체 초기화·이미지 영구 삭제는 범위와 영향을 확인하는 별도 동작으로 둡니다.

## 채택한 탐색 보조 도구

성분·Weight 잠금은 조합 상세·탐색 설정, 분기는 프로젝트 홈·세대 이력, Ablation은 조합 상세, 대표 Prompt·Seed 검증은 최종 후보·보관함, 비교 추천은 이미지 비교에 배치합니다. 새 상위 메뉴를 반복해서 추가하지 않습니다. [19번 문서](19_adopted_exploration_tools.md)에 작업 흐름과 독립 평가·채택·복원 조건을 정의합니다. 기존 HTML 목업이 이 추가 기능까지 지원한다고 표시하지 않습니다.
