2026-11-11. 기준 Commit `fa4983e`. 신규 조합을 한 번만 선택하고 끝내지 않고, 기존 순위표 안의 위치와 신규 조합 사이의 순서를 찾은 뒤 세대 선별을 완료합니다.

## 8389 조사와 변경한 정책

8389의 실제 Web 화면을 읽기 전용으로 확인하고 설치본의 `app/core.py`, `app/engine.py`, `web_browser/js/pages/arena.js`를 조사했습니다. 원본에는 일반 신규 Placement와 진화 자녀의 빠른 생존 판정이 구분되어 있습니다. 이전 CHS 진화는 최하위 부모에게 한 번 지면 종료되는 후자를 복원했습니다. 이번 요구에 맞춰 **전체 기존 순위표에서 위치를 찾는 자동 방식**으로 보강합니다. 원본과 모든 비교 순서가 같다는 의미는 아닙니다.

- 부모를 뽑는 범위는 기존 **상위 30%**입니다. 비교 기준은 부모로 제한하지 않고 해당 세대의 **전체 기존 활성 조합**입니다. 예를 들어 기존 조합 10개·부모 3개라면 10개를 기준으로 자리를 찾습니다.
- 기준 조합의 점수는 Batch 시작 시 고정합니다. 중간 위치부터 승패에 따라 이진 탐색하고, 비슷함·모순된 선택·승격 경계는 기존 검증 로직으로 추가 확인합니다. 모든 조합과 무조건 한 번씩 비교하는 방식은 아닙니다.
- 기존 조합 사이의 같은 구간에 신규 조합이 여럿 들어오면 신규끼리도 비교합니다. 같은 구간의 남은 대결이 점수를 바꿀 수 있으므로 그 묶음의 비교가 끝나기 전에는 모두 미확정 상태입니다.
- 미확정 조합은 `평가 중`과 `Elo —`로 표시하고 확정 순위에서 제외합니다. 한 표를 받았다는 이유만으로 평가 완료가 되지 않습니다. 선별 하단에는 자리를 확정한 조합 수와 기존 순위표/신규 조합 비교 상태를 표시합니다.
- 모든 기준 이미지가 준비되고 남은 Placement가 없어야 세대를 확정합니다. 생존 경계는 기존과 같이 **최하위 부모보다 위**입니다. 전체 순위표에서 위치를 찾도록 바뀌었다고 하위 자녀를 모두 생존시키지는 않습니다.
- 일반 신규 조합도 이미 평가된 기준 조합이 하나라도 있으면 그 순위표에 배치합니다. 기준이 전혀 없는 초기 Pool에서만 신규끼리 시작합니다.
- `전부`, `상위 30%` 비교 모드 선택은 추가하지 않았습니다. 이번 구현은 자동 Placement입니다.

## 진행 중인 세대와 저장 경계

정책 식별자는 `full-ladder-placement-v2`입니다. 서버 시작 시 계획/선별 중인 Batch의 JSON만 갱신합니다. Schema는 18 그대로이며 새 테이블을 만들지 않습니다.

기존 후보·부모·세대·이미지·작업과 Vote/Command 행, Undo Snapshot은 보존합니다. 기존 선택을 전체 순위표에서 다시 해석하므로, 한 번씩 선택한 뒤 완료로 표시됐던 **미확정 세대**는 추가 비교가 열릴 수 있습니다. 이미 확정하거나 취소한 Batch와 Checkpoint는 변경하지 않습니다. 계획만 만든 상태는 Revision을 바꾸지 않아 그대로 제출할 수 있습니다.

이전 Undo Snapshot을 되돌릴 때도 미확정 Batch를 현재 정책에 맞게 해석합니다. 명시적으로 보정한 Elo Offset은 유지하고, 미확정이라는 상태를 수동 점수 입력으로 우회하지 않습니다. 동시 Browser의 예전 Match Token은 새 정책으로 전환할 때 갱신합니다.
