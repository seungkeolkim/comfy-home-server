# Phase 0 피드백: 프로젝트 맥락·설정 경계·Fork

후속 진행: [1단계 프로젝트 저장·다시 열기](phase_one_review.md)를 실제 DB에 연결했습니다. 아래 Phase 0의 미구현 설명은 당시 목업 범위이며, 현재 실제 저장과 후속 생성·Fork의 경계는 1단계 안내를 따릅니다.

2026-11-10. Mobile에서 받은 피드백을 Desktop에도 공통 반영합니다. 기존 요구사항의 추가 결정 기록이며, 실제 탐색 Engine과 DB 구현 완료를 뜻하지 않습니다.

## 확정한 화면 수정

- 일반 생성 ↔ 스타일 구성은 양방향 같은 창에서 전환합니다. 초기 목업의 새 탭 처리는 입력 보존을 위한 임시 선택이었고 이번 피드백으로 제거했습니다.
- 여러 Prompt는 같은 조합 A/B를 검토할 자료입니다. **한 대결에서 모든 Prompt를 함께 보고 조합 하나를 한 번 선택**합니다. Prompt별 투표와 투표 방식 토글은 제공하지 않습니다.
- 차이 보기의 사용자 표시 강도는 작가·LoRA 모두 **STR**로 통일합니다. CLIP 등 실제 생성 입력은 내부 Snapshot에 보존하며 이 화면에서 숨겼다는 이유로 값을 바꾸지 않습니다.
- 그림체 목록은 현재 프로젝트만 보기를 기본으로 합니다. 전체 보기에서는 프로젝트별로 묶고 소유 프로젝트를 표시합니다.

2026-11-17 재확인으로 스타일 탐색은 [CLIP 1 고정](lora_clip_strength_policy.md)입니다. 앞으로 생성·새 등록하는 LoRA는 STR만 바뀌며 CLIP은 1입니다. 기존 Snapshot과 일반 생성의 독립 CLIP 설정은 보존합니다.

20번에 미정으로 남겼던 두 투표 방식 중 **조합 단위 한 번 선택**으로 결정됐습니다. 일반 Vote·Placement·Evolution Selection의 기존 의미를 유지하며 같은 선택을 Prompt 수만큼 중복 가산하지 않습니다. Parent Score 고정·Skip·Undo 계약도 유지합니다.

## 현재 프로젝트와 그림체 열람 범위

권장안은 **현재 탭의 공통 작업 프로젝트**와 **그림체 목록의 열람 필터**를 분리하는 것입니다. 이 안을 목업에 반영해 직접 확인할 수 있게 합니다.

| 동작 | 현재 프로젝트 | 그림체 목록 |
| --- | --- | --- |
| 상단 `현재 프로젝트` 변경 | 명시적으로 바뀜. 선별·설정·보관의 기본 대상 변경 | 해당 프로젝트만 보기로 전환 |
| 현재 프로젝트만 보기 | 유지 | 현재 프로젝트 소유 후보만 |
| 전체 프로젝트 보기 | 유지 | 프로젝트별 그룹으로 표시 |
| 다른 프로젝트만 열람 | 유지 | 선택한 프로젝트의 원본 결과를 참고 |
| 다른 프로젝트 그림체를 현재 조건에서 시험 | 유지 | 성분 Snapshot을 현재 프로젝트의 별도 시험에 가져오는 명시 동작 |

다른 프로젝트를 둘러봤다는 이유로 선별 대상이나 생성 요청 소속을 바꾸지 않습니다. 상단 현재 프로젝트를 항상 표시합니다. 다른 프로젝트의 이미지는 그 프로젝트의 원래 조건 결과이며 현재 Prompt로 만든 결과처럼 보여주지 않습니다.

프로젝트 선택을 로그인 Session 전체의 가변 서버 값 하나로만 구현하면 다른 탭의 선택이 현재 대결 대상까지 바꿀 수 있습니다. 따라서 탭별 선택을 화면 전체에서 공유하고, 서버 요청에는 Project/Evaluation/Match ID를 고정하는 방식을 권장합니다. Browser의 새로고침·공간 전환 후에도 같은 탭의 선택을 복구합니다. 다른 탭의 프로젝트 선택이 진행 중 대결에 자동 전파되지 않게 합니다.

현재 목업은 Session Storage로 예시 프로젝트·선택·보관·제외를 임시 보관합니다. 실제 프로젝트 영속 저장은 1단계에서 구현합니다. 일반 생성에서 스타일 구성으로 이동할 때는 생성 입력의 임시 Snapshot을 보관하고 돌아올 때 복구합니다. 비밀번호·파일 업로드 본체는 이 임시 Snapshot에 넣지 않습니다.

### 다른 프로젝트의 그림체 가져오기

`원본 프로젝트의 그림체 선택 → 현재 프로젝트에서 시험 → 대상 Prompt·생성 장수·호환성 확인 → 새 결과 생성 → 비교 후 채택` 흐름을 제안합니다.

- 가져올 것은 성분 Identity·순서·STR과 실제 생성에 필요한 독립 Strength Snapshot입니다.
- 생성 조건은 현재 프로젝트의 Workflow·Prompt Set·Seed 정책을 사용합니다. 원본 이미지·Elo·승패를 현재 순위에 합치지 않습니다.
- 현재 모델과 LoRA 호환성·파일 Hash·잠금·제외 규칙을 확인합니다. 성분을 몰래 바꾸지 않고 충돌을 해결하게 합니다.
- 현재 프로젝트 안의 별도 시험에서 새 관측으로 평가한 뒤 후보로 채택합니다. 대상/출처를 명시해 원본 프로젝트를 보존합니다.
- Phase 0의 버튼은 **시험 계획 미리보기**까지만 제공합니다. 실제 생성·시험·채택은 후속 구현입니다.

## 글로벌 설정과 프로젝트 설정

글로벌은 시스템의 연결·Catalog·기본값을 관리하고, 프로젝트는 특정 목적의 탐색 조건과 실제 사용 범위를 관리합니다.

| 범위 | 관리할 정보 | 적용 원칙 |
| --- | --- | --- |
| 글로벌 실행 환경 | Home에 이미 등록된 실행기·Comfy 연결 상태 | Home의 운영 설정·권한을 공유. 스타일 구성 전용 Endpoint/Port 입력·설정을 만들지 않음 |
| 글로벌 모델·파이프라인 | Workflow/Adapter·지원 기능, 모델 Identifier, 사용 가능한 LoRA와 호환성 근거 | Anima/Moss 등 모델별 계약을 구분. 미확인 호환성을 지원으로 단정하지 않음 |
| 글로벌 성분 Catalog | 작가 태그·LoRA Identity/Hash·Trigger·기본 STR 범위와 개별 기본값 | 성적·프로젝트 사용 여부와 분리. 파일 삭제와 사용 제외를 구분 |
| 프로젝트 목적·조건 | 이름·목적, 등록 Workflow/모델 선택, Prompt Set·Negative·Seed·크기·Sampling 조건 | 평가 구간의 불변 Snapshot으로 기록 |
| 프로젝트 탐색 범위 | 사용할 작가/LoRA, 개수·STR 범위, 제외·잠금·계보, 가져온 Prior | 글로벌의 가능한 후보 중 실제 탐색할 부분을 선택·조정 |
| 프로젝트 결과 | 조합·모든 Prompt의 Render·Vote·Elo·세대·보관 결과 | 프로젝트별 독립 |

새 프로젝트는 선택한 글로벌 기본값을 출처와 함께 초기 Snapshot으로 받아 시작하는 안을 제안합니다. 나중에 글로벌 기본 STR 범위를 바꿔도 기존 프로젝트 조건·점수·결과를 조용히 바꾸지 않습니다. 프로젝트에 새 기본값을 적용하려면 영향 Preview와 명시적 적용이 필요합니다. Prompt·모델 등 평가 의미가 달라지면 새 평가 구간 또는 재시험을 사용합니다.

프로젝트가 글로벌 실행기·Workflow 정의를 참조하더라도 요청에는 당시 설정/Version을 고정합니다. 파일이 사라지거나 연결 설정이 바뀌면 실행 전 확인하고 과거 조건을 재현할 수 있다고 가정하지 않습니다. 구체 Schema·설정 UI는 다음 작은 검토 단위에서 함께 확정합니다.

### 설정 목업 추가 피드백

- ComfyUI 연결은 Home Server와 공유합니다. 별도 실행기·Endpoint·Port 입력을 제거하며 실제 연결도 Home의 기존 설정을 사용합니다.
- 글로벌 Catalog와 프로젝트 탐색 범위 모두 작가 태그·LoRA를 별도 구역으로 구분합니다.
- 일본어로 표시되던 `STR固定`를 포함해 STR 고정 체크박스와 전용 고정값 입력을 제거합니다. 같은 강도는 최소=최대 범위로 표현하며 `0.4 ~ 0.4`를 유효하게 허용합니다. 이는 성분 필수 포함 잠금의 삭제를 뜻하지 않습니다.
- 성분 카드를 한 줄로 압축하지 않습니다. 오른쪽 여유 공간은 사용 횟수·선호 점수 등의 후속 정보에 사용할 수 있도록 유지합니다. 해당 통계의 실제 계산·표시는 아직 구현하지 않습니다.
- 이전 목업 Session의 고정 STR은 같은 최소·최대값으로 변환하고 전용 필드를 제거합니다. Prompt·프로젝트·초안과 기존 생성 성분의 독립 CLIP 값은 보존합니다.
- 글로벌 설정의 실행 환경 공유 안내 Panel도 불필요하다는 후속 피드백에 따라 제거합니다. Home 연결을 공유하는 내부 계약은 유지합니다.
- Workflow 옵션은 CHS의 이미지 Workflow 기준 비율·해상도, 너비·높이, Steps·CFG로 구성합니다. 해상도 후보를 공통으로 관리하고 사용자 지정 크기를 지원합니다. Seed 입력과 접힌 상세 영역은 제거하며 기존 생성 조건은 보존합니다.
- 작가 태그는 글로벌 설정의 줄 단위 Bulk 입력으로 신규 등록합니다. Style Lab의 이름 정리·중복 제외·등록 순서를 참고하며, 등록 전 미리보기와 확인 필요 줄의 수정을 제공합니다. 기존 프로젝트에서는 새 작가의 사용 여부를 직접 켜고, 새 프로젝트는 현재 글로벌 Catalog를 복사합니다. 실제 저장 전에는 탭의 예시 상태에만 반영합니다. 상세 범위는 [설정 목업 안내](settings_preview_review.md)를 따릅니다.

## 현재 상태와 특정 세대에서 Fork

기존 19번의 탐색 분기를 **Fork**라는 명확한 동작으로 이어갑니다. 현재 안정 상태 또는 실제 확정 Checkpoint에서 새 프로젝트를 만들며, 원본과 이후 탐색은 독립적입니다.

- 원본 조건·후보·점수·성분 설정·잠금·계보·보관·모든 Prompt 이미지 참조를 선택 시점 Snapshot으로 이어받습니다.
- Source Project/Checkpoint와 출발 세대 N을 표시하고 실제 다음 진화는 N+1로 진행합니다.
- ID와 변경 가능한 상태를 분리하고 원본 Vote를 새 Vote로 재생하지 않습니다. Fork 이전 Vote를 새 프로젝트에서 Undo하지 않습니다.
- 원본 복원·삭제가 Fork의 유효 이미지 참조를 삭제하지 않게 합니다.
- Checkpoint가 없는 과거 세대는 대상으로 제시하지 않습니다. 생성·투표 등이 진행 중인 상태는 안정 시점 확보 후 Fork합니다.
- 조건을 바꾸고 싶다면 Fork 후 별도 재시험으로 평가합니다. 옛 조건의 Elo를 새 Prompt에 그대로 넘기지 않습니다.

Phase 0에는 Fork 실행·세대 선택 화면이 아직 없습니다. 이후 Checkpoint·복원 기반을 만든 뒤 연결하며, 해당 차례에는 `출발 상태·새 이름·이어받는 범위` UI부터 확인합니다. 상세 계약은 [19번](19_adopted_exploration_tools.md)과 [15번](15_generation_restore_and_deletion.md)을 따릅니다.

## 현재 목업과 다음 검토 범위

현재 조작 가능한 화면은 프로젝트 목록·예시 생성 Form·선별·그림체 목록·성분 차이 창·범위 안내와 글로벌/프로젝트 설정 목업입니다. 추가로 [순위·상세·선별 왕복 목업](ranking_preview_review.md)을 그림체 탭에 통합해 예시 Elo·전적과 선택·Skip·Undo 변화를 확인할 수 있습니다. 통합 화면은 사용자 확인을 완료했습니다. 실제 설정 저장·생성·선별 Engine/유전 알고리즘, 재시험, Checkpoint·복원·Fork, 융합은 구현되지 않았습니다.

다음 UI 검토 단위로 **글로벌 설정과 프로젝트 설정의 구분**을 구현했습니다. 실행 환경/Catalog 기본값과 현재 프로젝트의 Prompt/성분 범위를 각각 어디서 설정하는지 다루며, STR 기본값 적용 전 변경 내용을 보여줍니다. [설정 화면 검토 안내](settings_preview_review.md)를 확인하세요. 사용자 확인 후 1단계 저장 구조에 연결합니다. 모든 후속 화면을 한꺼번에 만드는 계획으로 확대하지 않습니다.

진행 상태와 접속·검토 순서는 [Phase 0 안내](phase_zero_review.md), 단계별 개발 과정은 [development_process.md](development_process.md)를 기준으로 관리합니다.

## 사용자 확인과 보류 항목

사용자 후속 요청으로 별도 순위 메뉴를 그림체 탭에 병합했습니다. 그림체 카드의 Elo·전적·순위와 정렬·보관 필터를 한 화면에서 제공하며, Mobile 메뉴는 프로젝트 / 선별 / 그림체 / 설정 네 개입니다. 기존 프로젝트 열람 필터와 현재 작업 대상의 분리는 유지합니다. 병합 화면은 사용자 확인을 완료했고 Commit 요청을 받았습니다. [현재 목업 안내](ranking_preview_review.md)를 따릅니다.

2026-11-10 사용자가 첫 피드백 반영 목업을 확인하고 Commit을 요청했습니다. **그림체 탭의 프로젝트 선택 UI는 추후 수정**하며 이번에는 현 상태를 유지합니다. 구체적인 변경 방식은 아직 미정입니다. 이후 추가한 글로벌/프로젝트 설정, CHS Workflow 옵션과 작가 Bulk 등록 목업도 사용자가 확인하고 Commit을 요청했습니다. Fork UI와 실제 기능은 각 단계에서 별도로 확인하며 1단계 저장 구현은 아직 착수하지 않았습니다.
