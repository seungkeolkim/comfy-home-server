# 기존 기능과 복원 우선순위

## 현재 제품의 역할

Style Lab은 이미지 생성기 UI 위에 놓인 **주관적 선호 탐색 도구**입니다. 사용자는 작가·LoRA의 가중치 조합을 생성하고, 두 이미지를 비교해 선호를 누적하며, 상위 후보에서 다음 세대를 만듭니다. 학습 모델을 Fine-tuning하거나 LoRA 자체를 학습시키는 프로그램은 아닙니다.

현재 Desktop은 Python Engine과 pywebview/WebView2가 한 프로세스에서 동작합니다. Web 모드는 같은 Engine을 HTTP로 노출하며 Port 8389를 사용합니다. 데이터는 하나의 전역 `data/state.json`입니다. 프로젝트 기능은 없습니다.

## 기능별 복원 표

| 기능 | 현재 동작 | 새 구현 우선순위 |
| --- | --- | --- |
| 프로젝트 | 없음 | P0: 이름·목적·Workflow·평가 조건별 격리 |
| 특정 세대 복원 | 전체 Checkpoint 복원 없음. 현재 세대 취소·Vote Undo와 구분 | P0: 확인 후 이후 데이터 삭제와 당시 상태 복원 |
| 현재 조합 Prompt 재시험 | 상위 N개를 고정해 별도 재평가하는 기능 없음 | P0: 성분·가중치 유지, 시험 Elo·Drop·채택 |
| 후보 생성 | 작가·LoRA 수와 가중치 범위 내 무작위 생성, 중복 방지 | P0 |
| 선별 | A/B, 비슷함/Skip, Undo, Blind, 자리 찾기·리그 | P0 |
| 진화 | 상위 30% 부모로 변이·교차·무작위 후보 생성 | P0: 기본 유지, 여러 계보의 부모 기회 보강 |
| 그림체 목록 | 순위·Tier·승률·필터·Memo·북마크·부활 | P0: 목록·보관, 고급 일괄 편집은 P1 |
| 작가·LoRA 정보 | 등록·범위·Trigger·사용·승률·성분 점수 | P0 |
| 점수만 복제 | 없음. 점수는 조합에서 재계산 | P0: 명시적 Prior Snapshot |
| 여러 그림체 확보 | 조합별 북마크로 보존 | P0: 프로젝트별 복수 결과·Snapshot 내보내기 |
| 등록 Workflow 사용 | Style Lab 전용 간소 Workflow 또는 API JSON | P0: Home Server 등록본과 같은 Adapter 경로 |
| LoRA 적용 진단 | Model/TE/미확인/Patch 분리, 상세 기록 | P0: 최근 수정 동작 보존 |
| 융합 | 두 후보 태그 합치기, 겹친 가중치 평균, 생성 후 채택 | P2 |
| 다듬기 `tune` | 가중치 변형 다수 생성 → 선별 → 밀집 구간 추천 | P2 |
| 다듬기 `improve` | 챔피언 경쟁·다중 Round·다른 Seed 최종 확인 | P2, 최종 Seed 검증만 P1로 분리 가능 |
| 자유 생성 | Prompt를 직접 입력, 결과 채택 가능 | P1 |
| PNG Prompt Viewer | Metadata에서 Prompt·설정·작가 추출 | P1 |
| 데이터 Import/Export | State+PNG ZIP, 전체 교체 | P1: 프로젝트 단위 비파괴 Import |

`조합`은 기존 메뉴명이며 작가·LoRA 등록, 생성 규칙, 무작위 후보 생성까지 포함합니다. 새 UI에서는 이 중 필수 설정을 프로젝트 생성·설정으로 이동하고 수동 조합·융합 화면을 뒤로 미룹니다.

## 유지해야 하는 세부 UX

- 두 이미지가 준비되기 전 투표 금지. 키 반복·빠른 연타로 중복 투표하지 않기.
- A/B와 한 장씩 보기를 모바일에서 전환. 표시 위치를 바꿔도 의미상 A/B ID를 유지.
- Blind 중에는 점수·태그·전적을 가리고 투표 후 잠깐 결과 공개.
- 확대·이동을 양쪽에 함께 적용. 원본 열기, Prompt·LoRA 복사 지원.
- 프로젝트·메뉴 이동으로 작성 중 Prompt, 필터, 선택, Scroll을 임의 초기화하지 않기.
- 북마크된 후보는 진화 하위권 정리나 일괄 삭제에 휩쓸리지 않기.
- 오류 Toast와 상세 기록을 구분. Model Only의 예상 TE 미적용은 화면을 덮지 않기.

## 현재 한계와 복원 시 주의

1. Prompt·모델을 바꿔도 과거 조합·평가가 같은 전역 Pool에 남습니다. 다른 평가 조건의 점수가 섞일 수 있습니다.
2. 기존 후보는 이미지 하나에 대표됩니다. 고정 Seed 비교에는 유리하지만 특정 Seed에 과적합할 수 있습니다.
3. Registry의 `arena_wins`와 화면의 작가 점수는 서로 다른 통계입니다. 동일한 값처럼 저장하면 복원이 틀립니다.
4. 진행 중 Job·현재 대결·Undo Stack은 주로 메모리에 있습니다. 서버 재시작 후 완전한 작업 재개는 보장하지 않습니다.
5. 원본 README의 일부 용어·설명은 수정 전 기준입니다. 최근 LoRA 경고는 '레이어 로드 실패'가 아니라 Tensor Key 성분별 안내입니다.

원문은 [Snapshot 목록](source_reference/README.md)의 `app/engine.py`, `web_browser/js/pages/*`, `web_browser/js/ui.js`에서 확인합니다.
