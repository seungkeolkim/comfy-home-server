# 그림체 순위·상세·선별 왕복 목업 검토

2026-11-10. 설정·작가 Bulk 목업은 `69a2b0c`, 최초 순위·상세 목업은 `211be19`에 Commit했습니다. 이후 사용자 요청으로 순위를 **그림체 탭에 병합**했습니다. 현재 흐름은 **그림체의 순위·보관 → 상세 → 선별 복귀**이며, 병합 화면은 개발자 검증과 사용자 확인을 완료했고 Commit 요청을 받았습니다. 실제 DB 저장은 미착수입니다.

## 접속과 확인 순서

- Home의 **스타일 구성 → 그림체**, 직접 접속은 현재 Home 주소의 `/style-preview#candidates`입니다.
- Mobile 메뉴는 프로젝트 / 선별 / 그림체 / 설정 네 개이며 별도 순위 메뉴나 하위 탭은 없습니다.
- 이전 `#ranking` 주소·저장 상태·상세 복귀 대상은 그림체 화면으로 연결합니다.
- 기존 프로젝트 선택·열람 필터를 유지합니다. 전체 보기에서도 프로젝트별로 묶고 각 소유 프로젝트 안에서 순위를 계산합니다.

1. 기본 프로젝트의 카드에서 이미지·순위·Elo·평가 횟수·승패·Skip·보관 여부와 비교 부족·미평가를 확인합니다.
2. Elo 높은 순 / 평가 횟수 많은 순 / 등록 순으로 정렬하거나 보관한 그림체만을 켜 봅니다. 필터 안에서도 프로젝트 전체 순위는 유지됩니다.
3. 결과·전적 상세에서 모든 Prompt 결과·확대·작가/LoRA STR·전적을 확인하거나 보관하고 원래 화면으로 돌아옵니다. 필터·정렬·Scroll을 유지합니다.
4. 선별에서 A/B를 선택한 뒤 그림체 보기로 이동해 점수·순위 변화를 봅니다. Undo로 점수·전적·이전 A/B를 복구합니다.
5. 비슷함은 Elo·승패·평가 횟수를 유지하고 Skip만 기록합니다. Mobile 상세 왕복도 A/B·Prompt·한 장씩 보기의 쪽을 유지합니다.
6. Blind는 선별 이름·점수·상세 진입과 그림체·상세 화면을 가립니다. 명시적으로 Blind를 끄면 목록을 볼 수 있습니다.

확인할 내용은 카드의 정보 가독성, 정렬·보관 필터의 편의성, 상세·선별로 오가는 흐름입니다.

## 화면 범위와 상태

그림체는 기본 Elo 높은 순이며 미평가는 뒤에 배치합니다. 카드에서 미평가의 순위는 미평가, Elo는 `—`로 표시합니다. 등록 순은 원래 생성 순서이며, 표시 순서를 바꿔도 계산된 순위는 유지합니다. 보관 필터에 결과가 없으면 모든 그림체 보기로 해제할 수 있습니다.

다른 프로젝트 열람과 기존 시험 계획 미리보기는 현재 선별 대상을 바꾸지 않습니다. 다른 프로젝트의 성분·이미지·점수를 현재 프로젝트에 합치지 않습니다. 상세에서 작업 프로젝트를 바꾸면 새 프로젝트의 그림체 목록으로 이동합니다.

## 점수 예시와 실제 구현의 경계

기본 프로젝트 전적은 표시 상태를 위한 합성 요약이며 전체 대결 이력을 복원한 데이터가 아닙니다. 새 프로젝트는 모두 미평가로 시작합니다. 이전 Session의 프로젝트·후보·Prompt·선택·등록 작가·독립 CLIP 값은 보존합니다.

점수 변화는 [03번](03_selection_and_ranking_algorithms.md)의 일반 League Elo 수치인 시작 10000·K 320·Scale 4000과 짝수 방향 반올림을 참고합니다. 평가된 조합은 Elo·승률·경기 수·생성 순·ID로 정렬합니다. 비교 부족은 원본의 횟수 기준을 참고한 표시이며 신뢰구간이 아닙니다.

여러 Prompt를 함께 본 선택 한 번은 두 조합의 평가 한 번으로만 반영합니다. Skip은 무승부 Elo를 적용하지 않습니다. 선택 이력에서 점수·전적·순위를 재계산하여 Undo로 복구하며 보관 변경은 점수에 영향을 주지 않습니다.

**Placement·Evolution Selection·Tier·성분 점수 계산, 추천 Pair, 서버 Vote·동시성·영속 Undo는 미구현입니다.** 실제 연결에서는 Match Kind별 계약과 Golden Fixture를 별도 검증합니다.

이미지는 기존 예시 Prompt의 SVG입니다. 설정 변경으로 재생성하거나 새 조건의 실제 결과로 표시하지 않습니다. 모든 상태는 같은 탭의 Session Storage에만 보관하며 실제 DB·생성 작업에는 쓰지 않습니다.
