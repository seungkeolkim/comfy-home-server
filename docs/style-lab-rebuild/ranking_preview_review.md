# 그림체 순위·상세·선별 왕복 목업 검토

2026-11-10. 설정·작가 Bulk 목업은 `69a2b0c`에 Commit했습니다. 이후 사용자가 실제 연결 전 Elo·랭킹 화면 검토를 요청하여 **순위 → 상세 → 선별 복귀**를 작은 목업 단위로 추가했습니다. 이번 추가 화면은 구현·개발자 검증 완료, 사용자 확인 전입니다. 1단계 실제 저장은 아직 시작하지 않습니다.

## 접속과 확인 순서

- Home의 **스타일 구성 → 순위**를 사용합니다. Desktop은 왼쪽 메뉴, Mobile은 하단 메뉴에 있습니다.
- 직접 접속은 현재 Home 주소의 `/style-preview#ranking`입니다.
- 그림체 탭의 프로젝트 선택·열람 필터는 이전 보류 결정대로 유지합니다. 순위는 현재 프로젝트의 같은 예시 평가 조건 안에서만 표시합니다.

1. 기본 예시 프로젝트에서 Elo·평가 횟수·승패·Skip·보관 여부와 `비교 부족`·`미평가` 상태를 확인합니다.
2. `결과·전적 상세`에서 모든 Prompt 결과·이미지 확대·작가/LoRA STR을 확인하고 보관해 봅니다.
3. 선별에서 A/B 중 하나를 선택하고 직전 대결의 점수·순위 변화를 봅니다. 순위 화면에서도 같은 결과가 보이며 Undo로 복구할 수 있습니다.
4. `비슷함`은 Elo·승패·평가 횟수를 유지하고 Skip만 기록합니다. Undo는 Skip과 이전 A/B도 되돌립니다.
5. Mobile의 한 장씩 보기에서 B와 다른 Prompt를 선택한 뒤 상세를 열었다 돌아옵니다. A/B·Prompt·보는 쪽이 유지되는지 확인합니다.
6. Blind를 켜면 선별의 이름·Elo·상세 진입과 순위·상세를 가립니다. 순위를 보려면 명시적으로 Blind를 끕니다.

확인받을 내용은 세 가지입니다.

- 순위에서 이미지·Elo·전적·평가 상태를 파악하기 쉬운가요?
- 상세의 여러 Prompt 결과와 성분 배치가 편하고 선별로 돌아가기 쉬운가요?
- 선택·Skip·Undo 후 바뀌거나 유지된 내용이 충분히 보이나요?

## 화면 범위

| 위치 | 조작 가능한 것 |
| --- | --- |
| 순위 | 현재 프로젝트의 Elo 순서, Prompt Thumbnail 최대 2개, 전적·Skip·보관 상태 |
| 미평가 | 별도 구역. 순위·Elo는 `—`로 표시하고 비교 부족과 구분 |
| 상세 | 모든 예시 Prompt 결과·확대, 당시 조합 STR·전적·보관, 원래 목록/선별로 복귀 |
| 선별 | A/B 점수 요약·상세·순위 이동·직전 선택 변화 |
| 그림체 탭 | 기존 필터·소유 그룹 유지, 프로젝트별 순위·Elo 요약과 현재 프로젝트 상세 진입 추가 |
| Blind | 선별 점수·이름·상세 진입 숨김. 순위·상세는 가림 안내와 명시적 해제 |

열람으로 Pair Index·선택 이력을 변경하지 않습니다. 상세 복귀는 출발 화면·Scroll과 Mobile의 Prompt·보기 방식·A/B 쪽을 유지합니다. 상세에서 프로젝트를 바꾸면 새 프로젝트의 순위로 이동하여 이전 그림체를 다른 소속처럼 표시하지 않습니다.

## 점수 예시와 실제 구현의 경계

기본 프로젝트 전적은 상태를 보여주기 위한 합성 요약이며 전체 대결 이력을 복원한 데이터가 아닙니다. 새 프로젝트는 모든 조합이 미평가입니다. 기존 Session에는 순위 필드만 보충하며 프로젝트·후보·Prompt·선택·등록 작가를 보존합니다.

선택 변화는 [03번](03_selection_and_ranking_algorithms.md)의 **일반 League Elo** 수치인 시작 10000·K 320·Scale 4000과 짝수 방향 반올림을 참고합니다. 평가된 조합은 Elo·승률·경기 수·생성 순·ID로 정렬합니다. 미평가는 초기 내부 점수가 있어도 순위·Elo를 숨깁니다. 비교 부족은 원본의 횟수 기준을 참고한 표시이며 통계적 신뢰구간이 아닙니다.

여러 Prompt를 함께 본 선택 한 번은 두 조합의 평가 한 번으로만 반영합니다. `비슷함`은 일반 리그 Skip이며 무승부 Elo를 적용하지 않습니다. 선택 이력에서 점수·전적·순위를 재계산하므로 Undo 시 복구됩니다. 보관은 점수에 영향을 주지 않습니다.

**Placement·Evolution Selection·Tier·성분 점수 계산, 추천 Pair, 서버 Vote·동시성·영속 Undo는 미구현입니다.** 현재 순환 Pair와 예시 선택을 실제 선별 Engine으로 간주하지 않습니다. 실제 연결에서는 Match Kind별 계약과 Golden Fixture를 별도로 검증합니다.

이미지는 SVG 예시입니다. 상세는 기존 예시 Prompt 결과이며 설정을 바꿨다는 이유로 재생성하거나 새 조건의 실제 결과로 표시하지 않습니다. 원래 조합과 독립 CLIP 값을 유지합니다. 상태는 이 탭의 Session Storage에만 저장하며 실제 DB·생성 작업에는 쓰지 않습니다.

## 개발자 검증과 다음 단계

- Headless Edge에서 상태 구분·신규 프로젝트 미평가·조합 단위 한 번 평가·점수/순위 변화·정확한 Undo를 확인했습니다.
- Skip의 점수/전적 유지, 상세의 모든 Prompt·확대·STR·보관, Blind 가림·명시적 해제를 확인했습니다.
- 상세 왕복 후 A/B·Mobile Prompt·보는 쪽 유지, 프로젝트 격리·새로고침·기존 Session 선택 복구를 확인했습니다.

- 자산 allowlist와 기존 자산·Session 관련 테스트 5개가 통과했습니다. 기존 Phase 0 Browser 검증도 함께 확인합니다.
