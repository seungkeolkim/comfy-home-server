# Phase 0 화면 목업과 사용자 검토

2026-11-10. **첫 Mobile 피드백을 반영하고 Desktop·Mobile을 재검증했으며, 사용자가 그림체 탭의 프로젝트 선택 UI 외에는 확인 완료했습니다.** 해당 UI는 현 상태로 두고 후속 수정으로 남깁니다. 1단계 기능 구현은 아직 시작하지 않았습니다. 결정과 후속 설정/Fork 범위는 [21번](21_project_context_settings_and_fork.md)에 기록합니다.

## 접속

Comfy Home Server의 **스타일 구성 · Phase 0**를 누르면 같은 창에서 전환합니다. 일반 생성으로 돌아올 때 생성 입력을 복구하고, 다시 스타일 구성으로 오면 현재 프로젝트·화면·예시 선택 상태를 유지합니다.

- PC: `http://localhost:8388/style-preview`
- 다른 기기: 현재 사용하는 Home Server 주소 뒤에 `/style-preview`를 붙입니다.
- 로그인은 Home의 기존 Session과 비밀번호를 사용합니다.

8389의 Style Lab Web·Mobile을 UX 기준으로 삼아 선별·그림체 메뉴, A/B·비슷함·되돌리기·Blind·Mobile 한 장씩 보기 흐름을 유지했습니다. 이 페이지는 예시 화면이며 8389의 실제 탐색 상태와 연결하지 않습니다.

## 확인 순서

1. `새 프로젝트`에서 이름·Prompt를 수정합니다. Prompt를 하나 더 추가했다 제거해 예정 장수 변화를 확인합니다.
2. `예시 조합 만들기`를 누르고 그림체 두 개를 보관합니다. 실제 ComfyUI 생성은 실행하지 않습니다.
3. `선별 시작`에서 같은 A/B 조합의 두 Prompt 결과를 확인합니다.
4. 여러 Prompt의 결과를 보고 A/B 조합 중 하나를 한 번 선택한 뒤 `되돌리기`를 누릅니다. Prompt별 투표는 없습니다.
5. 상단 `현재 프로젝트`와 그림체의 `현재 프로젝트만 / 전체 / 특정 프로젝트` 필터를 사용해 봅니다. 다른 프로젝트를 열람해도 선별 대상은 유지됩니다.
6. `조합 차이 보기`에서 STR과 A/B 포함 여부를 확인하고 한 성분의 제외 설정·재허용을 눌러봅니다.
7. `Blind`에서 성분 이름·차이 보기가 숨겨지는지 확인합니다. Mobile에서는 Prompt 전환과 `한 장씩`·`A/B 보기`를 사용해 봅니다.

## 이번에 판단할 세 가지

1. **시작과 이동:** 프로젝트 → 조합 → 선별 흐름이 자연스럽고, 현재 8389 Web의 익숙한 조작을 충분히 유지했나요?
2. **여러 Prompt 비교:** 조합 단위 한 번 선택으로 통일했습니다. Mobile의 이미지 크기·Prompt 전환과 Desktop의 Matrix 배치가 판단하기 편한지 봐 주세요.
3. **성분 차이와 제외:** 긴 한 줄보다 변경점을 이해하기 쉬운가요? 차이 창의 위치와 제외 버튼의 범위가 분명한가요?

사용자는 위 피드백 반영 결과를 확인하고 Commit을 요청했습니다. **그림체 탭의 프로젝트 선택 UI는 나중에 수정**하며, 구체적인 변경 방식은 아직 미정입니다. 이 확인은 현재 목업 범위에 한정되며, 미구현 설정·Fork 화면의 확인이나 다음 단계 착수를 뜻하지 않습니다. 다음 단계는 별도 요청에 따라 진행합니다.

## 목업의 정확한 범위

| 기능 | 현재 가능한 것 | 남은 구현 |
| --- | --- | --- |
| 작업 공간·프로젝트 선택 | 같은 창 전환, 탭 공통 현재 프로젝트, 생성 입력·예시 상태 임시 복구 | 실제 프로젝트 DB 저장·접속 복구 |
| 프로젝트 만들기 | 이름·Prompt 묶음·조합 수 Form과 장수 예시 | 실제 Workflow·성분 Catalog 연결과 DB 저장 |
| 선별 | SVG 예시를 여러 Prompt에서 보고 조합 단위 한 번 선택, Undo·Blind·Mobile 보기 | 실제 이미지 생성, Elo·Selection·성분 통계·유전 알고리즘 |
| 조합 차이 | STR 차이와 제외·재허용의 조작 예시 | 실제 후보 생성의 제외/잠금 정책 적용 |
| 그림체의 순위·상세 | 카드의 예시 Elo·전적·미평가, 정렬·보관 필터, 모든 Prompt 상세·보관·선별 복귀, 선택/Skip/Undo 변화 | 실제 Match Kind별 평가·점수·추천 Pair·DB 연결 |
| 그림체 | 현재 프로젝트 기본 필터, 전체의 프로젝트별 그룹, 복수 보관 예시 | 실제 SavedStyle Snapshot·일반 생성 적용 |
| 다른 프로젝트 그림체 시험 | 원본과 현재 대상 Prompt를 보여주는 계획 미리보기 | 호환성·장수 확인, 새 결과 생성·비교·채택 |
| 글로벌/프로젝트 설정 | 별도 설정 Form, 프로젝트별 초안, STR 기본값 적용 Preview·취소 | 실제 운영 설정·Catalog·DB 저장 연결 |
| 세대 복원·Fork | 요구사항·독립성·Checkpoint 계약 문서 | 세대 이력·선택 UI, Snapshot·삭제 영향·실제 복원/Fork |
| 진단·검증·융합 | 우선순위·작업 범위 문서 | Ablation·추가 Prompt/Seed·이관·비율/3개 이상 융합 UI와 실제 기능 |

프로젝트·일러스트는 예시이며 모델의 실제 성분 효과나 품질을 재현하지 않습니다. 목업 상태는 이 탭의 Session Storage에 임시 보관되고 DB에는 저장하지 않습니다. 서버에는 화면 GET Route와 기존 인증만 사용하며 새 생성·저장 API나 DB Migration을 추가하지 않았습니다.

화면 상단 **현재 범위·남은 구현**에서도 같은 경계를 확인할 수 있습니다. 후속 작은 단위로 글로벌·프로젝트 설정, CHS Workflow 옵션과 작가 Bulk 등록을 추가했으며 이 범위도 사용자 확인을 완료했습니다. [설정 화면 접속·검토 기록](settings_preview_review.md)을 확인하세요. 실제 저장·생성 등 나머지 기능은 별도 진행 요청을 받은 뒤 구현합니다.

## 개발자 검증

- 8388 서버 재시작 뒤 Session·일반 생성·목업의 HTTP 응답과 Container healthy 상태를 확인했습니다.
- Headless Edge에서 Desktop과 Mobile, 가로 폭 320·390·768·1280px를 확인했습니다.
- 같은 창 양방향 전환, 일반 생성 Prompt/Negative/Steps/설명 복구, 현재 프로젝트·화면·선택의 새로고침 후 복구를 확인했습니다.
- 단일 조합 투표, Undo·Blind, STR만 표시, 프로젝트별 독립 후보, 전체 보기의 그룹과 선별 대상 유지, 가져오기 계획 Preview, Mobile 한 장씩 보기를 확인했습니다.
- Mobile 투표 영역이 이미지를 덮지 않도록 수정하고 배치를 다시 검증했습니다.
- 목업 조작 중 생성·저장 API 요청이 없고, 로그인하지 않은 기존 API 요청은 거부되는 것을 확인했습니다.
- 고정 화면 파일만 허용하는 Route 검증과 기존 화면 자산·Session 관련 테스트 5개가 통과했습니다.
- 운영 DB Schema는 14, `style_*` 테이블은 0개입니다. 검증 전후 Home Request 수는 3024개로 동일했습니다.

검증용 스크립트·화면 캡처는 Git에서 제외된 `runtime/verification/phase-zero-*`에 있습니다. 제품 파일은 `web/style-preview/`, Route는 `home_server/style_preview.py`입니다.
