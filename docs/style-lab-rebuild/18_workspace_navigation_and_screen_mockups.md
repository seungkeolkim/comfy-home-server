# 작업 공간 전환과 Desktop·Mobile 화면 설계

2026-11-09 작성. Comfy Home Server 내장 구현을 전제로 한 UI 제안이며 실제 서비스 화면은 아직 변경하지 않았습니다. 기존 Style Lab의 메뉴 구성을 재현하는 대신 프로젝트와 비교 작업을 중심으로 구성합니다.

2026-11-10 추가: UX 기준은 localhost:8389의 실제 Style Lab Web·Mobile 사용 경험입니다. [20번 문서](20_web_ux_fusion_multi_prompt_and_component_differences.md)의 다중 Prompt 비교·성분 차이/제외를 초기 화면안에, 비율 지정·3개 이상 융합을 후순위 별도 화면안에 반영합니다. 아래 메뉴와 기존 HTML 목업은 이 요구에 맞춰 사용자와 다시 검토할 제안이며, 새 기능을 이미 지원하는 화면이 아닙니다.

## 두 작업 공간

상단에 **일반 생성 / 스타일 구성**을 항상 같은 순서로 둡니다. 일반 생성의 기존 메뉴는 그 안에 유지하고, 스타일 구성은 독립적인 프로젝트 메뉴를 사용합니다. 생성 버튼 옆에 작은 Mode 설정을 넣으면 일반 생성의 옵션처럼 오해하기 쉬우므로 작업 공간 자체를 전환합니다.

| 공간 | 책임 | 시작 지점 |
| --- | --- | --- |
| 일반 생성 | 자유로운 이미지·영상 생성, 기존 작업·결과물·Prompt·태그·LoRA Preset 관리 | 마지막 일반 생성 화면과 입력 |
| 스타일 구성 | 프로젝트별 조합 탐색·비교·계보 유지·Prompt 재시험·세대 관리·스타일 보관 | 마지막 스타일 프로젝트와 화면, 처음에는 프로젝트 목록 |
| 공통 영역 | 인증, 등록 Workflow, 전체 Job 상태, Output 관리 기반 | 상단 `작업` 버튼으로 전체 Job 접근 |

전환 자체는 생성·취소·입력 복사를 실행하지 않습니다. 작성 중인 Prompt·설정·Filter·선택 ID·Scroll·비교 배치를 `workspace + project + evaluation + trial` 범위에 맞게 보존합니다. 두 공간을 별도 탭으로 열어도 실제 생성 요청은 제출 시 고정한 소속을 유지합니다.

실제 구현의 URL 제안은 `/generate`, `/style/projects`, `/style/projects/{project_id}/{section}`입니다. 현재 Home Router 구조에 맞춰 확정하되 프로젝트·Trial·Evaluation 식별자를 경로 또는 명시적 Query로 보존합니다. 재접속 시 완료된 작업을 자동 재제출하지 않습니다.

## 전체 구조

```text
Comfy Home
├─ 일반 생성
│  ├─ 생성
│  ├─ 작업 / 결과물
│  └─ Prompt / 태그 / LoRA Preset
└─ 스타일 구성
   ├─ 모든 프로젝트
   ├─ 새 프로젝트
   ├─ 보관한 스타일
   └─ 선택한 프로젝트
      ├─ 프로젝트 홈
      ├─ 이미지 비교
      ├─ 현재 조합
      ├─ Prompt 재시험
      ├─ 세대 이력
      └─ 프로젝트 설정
```

진화는 `다음 세대 만들기`라는 실행 동작입니다. 별도 상위 메뉴보다 프로젝트 홈과 비교 완료 지점에서 접근하게 합니다. 실행 전 부모·계보별 배정·후보 수·Mutate/Crossover/Random 계획을 확인합니다. 진행 상황은 프로젝트 홈과 Job 상세에서 확인합니다.

## Desktop Web의 전환

상단 왼쪽 Brand와 `일반 생성 / 스타일 구성`, 오른쪽 전체 `작업`을 유지합니다. 스타일 구성의 왼쪽 메뉴에는 `모든 프로젝트`, `보관한 스타일`, 선택한 프로젝트의 하위 화면을 배치합니다. 본문에는 프로젝트명·세대·Evaluation을 고정된 경로 정보로 표시합니다.

왼쪽 메뉴를 기본안으로 제안합니다. 별도 상단 Tab을 중복 배치하지 않습니다. 대안인 상단 메뉴는 목업의 디자인 조절 기능으로 확인할 수 있으며 제품에 두 Navigation을 동시에 노출하는 제안이 아닙니다.

비교 화면은 이미지가 중심입니다. 평소에는 Seed·CFG 등 짧은 조건 요약만 보여주고 상세를 펼쳐 확인합니다. Blind일 때는 점수·성분·스타일 이름을 가립니다. 지금 평가 중인 대상이 원본 탐색인지 Prompt 시험인지는 항상 표시합니다.

## Mobile Web의 전환

상단 첫 줄에는 Brand와 전체 `작업`, 둘째 줄에는 `일반 생성 / 스타일 구성`을 둡니다. 공간 전환을 `더보기` 안에 숨기지 않습니다.

스타일 구성 하단 메뉴는 **비교 / 조합 / Prompt 시험 / 더보기** 네 개입니다. `더보기`에는 프로젝트 홈·모든 프로젝트·세대 이력·보관한 스타일·설정을 둡니다. 프로젝트명 또는 경로에서 홈·프로젝트 목록으로도 이동할 수 있습니다. 일반 생성으로 전환하면 해당 공간의 하단 메뉴로 바뀝니다.

실제 앱에서는 하단 메뉴를 Safe Area 위에 유지하되 본문 하단 Padding으로 내용을 가리지 않게 합니다. 대화 속 목업은 전체 내용이 잘리거나 내부 Scroll이 생기지 않도록 하단 메뉴를 문서 흐름에 배치했습니다.

비교는 두 방식을 지원합니다.

- **나란히**: 두 장을 같은 크기로 표시하고 각 이미지 아래에서 A/B를 선택합니다.
- **한 장씩**: A/B 표시와 `다른 이미지 보기`로 전환합니다. 표시 중인 이미지에 대한 선택 버튼을 명확히 둡니다. 실제 구현에서는 양쪽 Render 준비·확인 정책을 공통으로 검증합니다.

Touch Target은 약 44px 이상으로 확보하고, 길게 누르기나 Hover 없이 핵심 동작을 수행할 수 있게 합니다. 가로 폭 320px에서도 생성·투표·Drop 버튼과 확인창이 잘리지 않아야 합니다.

## 중요한 상태와 확인 동작

### Prompt 재시험

`현재 조합` 또는 프로젝트 홈 → 상위 N개 확인 → 새 Prompt 입력 → 고정 조합 생성 → 시험 내부 비교 → Drop/취소 → 시험 보관 또는 채택 순서입니다.

시험 순위는 `시험한 N개 중 순위`이며 기존 전체 Pool 순위와 구분합니다. 후보별 작가·LoRA·Weight와 공통 생성 조건을 유지하고, 새 Elo는 10000/전적0에서 시작합니다. 채택하면 `12세대 / Prompt 시험 B`처럼 표시하고 세대는 올리지 않습니다. 남은 후보 수와 평가 수가 진화 조건을 충족하지 못하면 다음 세대 실행을 막고 필요한 작업을 안내합니다.

Drop은 시험 한정이며 원본 삭제가 아닙니다. 원본과 신규 이미지의 나란히 보기는 참고용으로 제공하고 두 조건을 섞어 Elo를 계산하지 않습니다. 현재 목업은 원본/신규 Image Toggle 대신 Trial과 원본 목록을 오가며 확인하는 수준입니다. 생성·Job 완료·채택 충돌 등 실제 계약은 [17번 문서](17_prompt_retests_and_reranking.md)를 따릅니다.

### 다음 세대

확정 부모와 계보 대표, 새 후보 수·생성 방식별 배정·유지 정책을 보여준 뒤 제출합니다. 순위와 생성 예산이 맞지 않으면 조정 이유를 안내합니다. 보관한 후보와 계보 대표는 다른 기능으로 표시합니다.

### 세대 복원

세대 선택 → 삭제 영향 계산 → **확인창 한 번** → 복원 순서입니다. 이후 이미지·이력·승패·Elo·보관 결과의 삭제와 당시 상태 복원을 안내합니다. 독립 채택 구간·공유 Asset은 [15번 문서](15_generation_restore_and_deletion.md)의 범위대로 처리합니다.

### 일반 생성과 스타일 보관함 연결

스타일 보관함의 `일반 생성에 가져오기`는 명시적 적용 동작입니다. 덮어쓸 성분·Weight와 모델·Workflow 호환성 차이를 확인합니다. 단순한 공간 전환은 아무 설정도 복사하지 않고 생성도 제출하지 않습니다.

## 빈 상태·실패·진행 중 상태

- 프로젝트 없음: `새 프로젝트`와 Fresh/점수 이전 설명을 표시합니다.
- 후보 생성 중: 완료 수와 실패 수를 분리하고 성공한 비교 가능 후보만 엽니다. Browser 종료 뒤에도 서버가 추적합니다.
- 시험 N=1: 생성·보관은 가능하지만 A/B 비교는 비활성화하고 이유를 표시합니다.
- 실패·Drop으로 비교 가능 후보가 2개 미만: 비교 비활성, 재시도·Drop 취소·추가 시험 안내.
- 모델·LoRA 누락/Hash 변경: 실행 전에 대상별 호환성 안내, 임의 대체나 Weight Clamp 금지.
- 오래된 Vote·채택·복원 Token: 409와 현재 상태 표시. 사용자 선택을 새 대상에 자동 적용하지 않습니다.
- 예상 TE 미적용: 반복 Toast 대신 작업 상세의 적용 기록. 실제 Patch 오류는 지속적인 실패 상태와 상세 Log 제공.

## 추가 채택 기능의 화면 진입점

[19번 문서](19_adopted_exploration_tools.md)의 다섯 기능을 기존 화면 안에 배치합니다. 아래는 확정 요구사항의 추가 설계이며 현재 HTML 목업에 구현됐다는 의미가 아닙니다.

| 기능 | Desktop Web | Mobile Web | 확인할 내용 |
| --- | --- | --- | --- |
| 일부 잠금 | 조합 상세·탐색 설정에서 성분 유지/강도 축 고정 | 성분 상세 Sheet에서 범위·축 선택 | 프로젝트/계보 범위, 충돌·호환성, 다음 생성 적용 Revision |
| 탐색 분기 | 프로젝트 홈·세대 이력의 분기 버튼 | 같은 화면의 추가 작업 메뉴 | 새 이름·출발 Snapshot·이어받을 통계·이미지 참조·독립성 |
| Ablation | 조합 상세에서 Baseline과 변형을 나란히 비교 | 기준/변형 전환과 선택 변형 보기 | 한 변경의 Delta·공통 조건·신규 장수·원본 비변경·새 후보 채택 |
| 대표 Prompt·Seed 검증 | 최종 후보·보관함에서 Case별 결과 Matrix | Case 선택 후 후보·Seed 결과 비교 | Suite Version·생성 장수·조건별 판정·부분 실패 |

분기는 삭제 확인창이 아닌 새 프로젝트 생성 흐름으로 제공합니다. 세대 복원은 기존대로 이후 데이터를 삭제하는 별도 동작입니다. 진단·검증 화면에서 원본 Elo와 별도 평가 점수를 함께 보여줄 때 범위를 명확히 표시합니다.

## 목업과 검증 범위

[목업 실행·편집 안내](mockups/README.md)를 참고하세요. Desktop·Mobile은 동일한 예시 데이터와 공통 동작을 사용하며 화면 배치만 나눕니다. 모든 이미지·점수·작업 수는 설명용이며 API·DB·ComfyUI에 연결하지 않습니다. 합성 풍경은 이미지 영역과 비교 배치를 보기 위한 도형입니다. 실제 모델의 출력 품질이나 Style 차이를 보여주는 자료가 아닙니다.

주요 화면의 Desktop 1280px, Mobile 390px와 320px 축소 배치, Light/Dark 테마, 작업 공간 전환 후 입력 유지, 시험 Elo 격리·Drop/취소·채택의 세대 유지, 단일 복원 확인창을 Browser에서 확인합니다. 이는 운영 API·GPU 생성·실제 복원 기능의 검증을 대체하지 않습니다.
