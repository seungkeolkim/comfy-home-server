# 이미지 생성의 그림체 탭 통합

2026-11-15. 사용자가 별도 이미지 생성 탭의 중복을 검토한 뒤 통합 구현을 요청했습니다. `/style`의 현재 동선은 이 문서를 따릅니다. 기존 목업·단계별 기록의 다섯 탭 구성보다 우선합니다.

## 사용 흐름

- Mobile 하단과 Desktop Sidebar의 프로젝트 메뉴는 **프로젝트 / 그림체 / 선별 / 진화**입니다. 프로젝트 카드에서 작업을 이어가면 그림체가 열립니다. 프로젝트·글로벌 설정은 기존 설정 진입점을 사용합니다.
- 그림체 상단의 **＋ 조합 생성**으로 생성 창을 엽니다. Random 수량·50개까지 확장과 접힌 직접 조합 지정을 기존 입력·계획·Submit 처리로 실행합니다. 창 열기·닫기·화면 이동은 계획이나 GPU Job을 만들지 않습니다.
- 생성 장수의 명시적인 확인창을 유지합니다. 취소하면 생성 입력으로 돌아가며 같은 계획으로 재시도할 수 있습니다. 확인 후에는 생성 창을 닫고 활성·진화 중 그림체 카드에서 상태와 결과를 확인합니다.
- 새 Prompt 저장 뒤 가능한 기존 조합 재생성은 그림체의 **같은 조합으로 다시 그리기**로 실행합니다. 조합 성분을 새로 추첨하지 않습니다.
- 결과는 Prompt 수와 관계없이 기존 조합별 카드와 공통 Viewer로 표시합니다. 생성 중 장수·취소·실패 재시도를 유지하고, 개별 오류는 해당 카드의 접힌 생성 오류에서 확인합니다. Elo·정렬·일괄 선택·폐기 기능을 재사용합니다.
- 다음 세대 자녀 생성·선별 진행·세대 확정·취소·이력은 진화에 남습니다. Random 신규 추가와 진화 요청을 별도 동작으로 유지하며 세대 확정이 다음 GPU 생성을 자동 실행하지 않습니다.

## 상태와 성능

- 생성 창의 수량·직접 조합 입력은 기존 프로젝트별 상태를 사용합니다. 닫았다 열어도 유지하고 프로젝트를 바꿀 때 섞지 않습니다. 다른 화면·프로젝트로 이동하면 이전 생성 창을 닫습니다.
- 기존 `#generation` 주소와 Session의 `generation` 화면은 `#candidates`로 연결합니다. 주소 복구는 생성 창이나 확인창을 자동으로 열지 않습니다.
- 생성 입력 창은 결과 목록과 독립적으로 갱신합니다. 기존 Summary 조회·중복 Polling 병합·같은 이미지 노드 재사용·Thumbnail Cache를 유지하고, 삭제한 생성 결과 화면의 상세 Prompt·Settings 조회는 반복하지 않습니다.
- 같은 프로젝트의 투표 처리 중 생성 변경을 막는 기존 Guard와 계획 Revision·Operation ID·중복 Submit 방지를 유지합니다. 생성 창에는 별도 DB나 생성 API를 추가하지 않습니다.

## 확인할 항목

- 네 탭·프로젝트 카드·이전 주소 및 Session 복구, 창 열기만으로 생성되지 않는지 확인합니다.
- Random·직접 조합·새 Prompt 재생성, 확인 취소·Escape·재시도·Reload, 진행 취소·실패와 오류 표시를 확인합니다.
- 320/390/768/1280px, 프로젝트별 초안, 정렬·다중 선택, Mobile Thumbnail과 Desktop 원본 Viewer를 확인합니다.
- 기존 투표·Undo·같은 프로젝트 동시 조작 방지와 진화·세대 확정의 회귀 검증을 수행합니다.
- 운영에서는 생성·투표 없이 화면과 정적 파일을 확인하고 기존 DB·스타일 이미지 보존을 대조합니다.

## 검증 결과

- Python 정적 자산 제공 검사 1개와 JavaScript Syntax·`git diff --check`를 통과했습니다. Backend와 DB Schema 변경은 없습니다.
- Fake Comfy와 임시 PNG를 사용하는 Browser 13개 시나리오가 통과했습니다. 프로젝트, 통합 생성, 직접 생성, Random 생성, Prompt 수정·동일 조합 재생성, 평가 후 Random 추가, Pool 확장, 진화, 투표·Undo, 조합 관리·Viewer, 설정 피드백, 선별 조작, 그림체·비교 Scroll을 확인했습니다.
- 새 시나리오는 320/390/768/1280px, 주소·Session 복구 시 자동 생성 없음, 확인 취소·Escape, 프로젝트별 생성 입력과 기존 정렬·선택 유지, Summary 전용 조회를 검증합니다. 진행·취소·실패 오류의 안전한 표시와 `retryFailedOnly` 전달도 UI 응답을 제어해 확인했습니다.
- 운영 8388에 반영하고 재기동하여 `running / healthy`를 확인했습니다. 동일한 네 해상도에서 실제 카드·생성 창·공통 Viewer·이전 주소 연결을 확인했으며 Browser의 상태 변경 요청과 오류는 0건입니다. 제공 자산 7개의 Hash가 검증한 소스와 일치합니다.
- 반영 전후 업무 테이블 32개의 수량·내용 Hash와 실제 스타일 이미지 595장의 Hash가 같습니다. Schema 18, `quick_check=ok`, Foreign Key 위반 0건이며 운영 GPU 생성·투표는 하지 않았습니다.
- 운영 DB·기존 소스 Backup은 `runtime/style-library-generation-deployment-20261115-220304/`, Browser 결과는 `runtime/verification/style-library-generation/`입니다. 이미지 파일은 복사한 Backup이 아니라 전후 Hash로 보존을 확인했습니다.
