# 1단계: 실제 프로젝트 저장·다시 열기

2026-11-10. Fresh 프로젝트 저장을 CHS SQLite에 연결하고 개발자 검증을 마쳤습니다. 사용자가 프로젝트 UI 구성을 확인하고 Commit을 요청했습니다. UI 디테일은 후속 수정으로 남기며, 실제 이미지 생성은 다음 2단계입니다.

## 접속과 확인 순서

Home의 상단 **스타일 구성**으로 이동하거나 현재 Home 주소의 `/style`을 엽니다. PC에서는 `http://localhost:8388/style`입니다. 기존 `/style-preview`는 별도의 예시 목업으로 유지하며 그 Session과 예시 데이터를 실제 DB로 가져오지 않습니다.

1. **새 프로젝트**를 누르고 이름·목적, Positive Prompt 두 개와 공통 Negative를 입력합니다. 등록 Workflow·비율·해상도·Steps·CFG를 확인하고 **프로젝트 저장**을 누릅니다.
2. 저장 후 프로젝트 설정이 열립니다. 이름이나 메모를 바꾸고 **서버에 저장**을 누릅니다. 프로젝트는 조합 0개·투표 0회·1세대이며 이미지를 자동 생성하지 않습니다.
3. 다른 Prompt의 두 번째 프로젝트를 만듭니다. 상단 현재 프로젝트로 오가며 이름·Prompt·크기·성분 범위가 섞이지 않는지 확인합니다.
4. 미저장 메모를 작성한 채 프로젝트를 바꾸거나 새로고침해 봅니다. 같은 탭의 초안은 유지됩니다. 다른 기기에서는 서버에 저장한 값이 보이고, 탭별 현재 프로젝트 선택은 독립적입니다.
5. 글로벌 설정에서 작가를 줄 단위로 등록하고 STR 기본값을 저장합니다. 기존 프로젝트는 그대로이고 새 프로젝트 작성 시작 시 당시 글로벌 기본값을 복사합니다. 기존 프로젝트는 새 작가를 직접 선택하며 STR 기본값은 Preview 후 가져옵니다.

이번 사용자 확인은 프로젝트 UI 구성에 대한 수락입니다. 기기 간 저장·동시성 등 기술 검증 결과는 아래 개발자 검증 기록과 구분합니다. 현재 요청은 Commit과 다음 작업 안내까지이며, 별도의 다음 단계 진행 요청을 받으면 실제 생성 연결에 착수합니다. 구체적인 UI 디테일 수정 항목은 아직 지정되지 않았습니다.

## 실제 연결 범위

- CHS의 로그인·동일 출처 보호와 DB를 공유합니다. Comfy 연결·Port 설정은 별도로 만들지 않습니다.
- 현재 Style 생성 대상으로 연결한 등록 이미지 Workflow는 Anima입니다. Model은 등록 Graph에서 읽고 지원하는 너비·높이·Steps·CFG만 편집합니다. MiniMax 영상·Moss는 지원 완료로 표시하지 않습니다.
- ComfyUI의 설치 LoRA 목록을 읽어 표시합니다. 파일 존재를 모델 호환성 검증으로 표시하지 않으며 사용할 LoRA를 사용자가 허용합니다. 작가 Catalog는 직접 등록하며 목업 작가·LoRA를 자동 등록하지 않습니다.
- 프로젝트별 이름·목적·Prompt Set·공통 Negative·생성 조건·성분 사용 여부·STR 범위를 저장합니다. 최소=최대 STR도 허용합니다.
- Case ID와 순서를 보존하고 Workflow API/UI·Model·Template Hash·내부 Seed·조합 단위 한 표 정책을 불변 평가 Snapshot으로 저장합니다. 이름·메모·성분 범위 변경은 기존 평가 조건을 바꾸지 않습니다. Prompt·크기·Sampling 조건 변경은 새 Snapshot을 추가하고 이전 기록을 유지합니다.
- 다른 탭이 먼저 저장했으면 오래된 초안 저장을 409로 거부하며 초안을 유지합니다. **서버에서 다시 불러오기**로 최신 서버 상태를 읽고 **초안 되돌리기**로 저장된 설정을 다시 편집할 수 있습니다.
- 생성 요청 ID로 중복 프로젝트 생성을 막고, 프로젝트 편집은 Revision을 검사합니다. 저장 실패를 성공으로 표시하거나 자동 재제출하지 않습니다.
- 일반 생성 ↔ 스타일 구성은 같은 창에서 이동하며 일반 생성의 작성 중 입력을 보존합니다.

## 22번 작업·출력 분리와의 경계

프로젝트에 안정적인 소유 ID와 예정 출력 루트·모델 폴더·프로젝트 폴더를 연결합니다. 프로젝트 이름을 바꾸면 예정 프로젝트 폴더명도 바뀝니다. 현재 상태는 `not_created`이며 실제 작업분류·파일·출력 폴더를 만들지 않습니다.

자동 작업분류·세대부터 시작하는 메모, 실제 전용 출력·프로젝트 Rename Operation·파일 참조 갱신, 일반 작업/이미지 표시 Checkbox와 이동 제한은 2단계 실제 생성 연결에서 구현합니다. 이번 단계에서 실제 폴더 Rename·이동 차단이 완성됐다고 해석하지 않습니다.

선별·그림체는 빈 상태로 표시합니다. 예시 이미지·가상 Elo·후보를 실제 결과로 표시하지 않으며 Vote·진화·보관·재시험·복원·Fork는 아직 연결하지 않았습니다.

## 저장·Migration·운영 검증
