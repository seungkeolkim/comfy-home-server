## 검증 범위의 한계

- 원본 취소의 최종 파일 삭제는 실행하지 않았습니다. 삭제 경고·가능 조건은 실제 UI에서, 삭제 효과는 현재 Engine Source에서 확인했습니다. 이를 실제 삭제 검증 완료라고 표시하지 않았습니다.
- 기존 Pool·Prompt·Seed가 서로 달라 실제 Vote 횟수로 이미지 품질이나 알고리즘 우열을 비교하지 않습니다. 같은 입력의 정책 차이는 별도 합성 Source 실행으로 보완했습니다.
- StyleLab 기본 개수 두 값은 1로 변경된 채이며, 생성한 이미지·투표·확정 이력과 CHS 새 조사 프로젝트는 남겨 두었습니다. 원래 상태로 완전히 되돌린 조사가 아닙니다.
- 비교 기준은 현재 로컬 8389 Web 모드입니다. 배포 바이너리 전체를 실행·복원했거나 모든 부가 기능이 동일하다는 판정이 아닙니다.

현재 CHS는 생성·선별·진화의 한 Cycle을 실행할 수 있습니다. 최소 기능의 재현 품질을 높이려면 재현 결함 수정과 선별 정책 계약·UI 조작 경험 정리를 이어가야 합니다. 그 구현은 이번 조사 완료와 별도의 후속 작업입니다.

최종 파일 검증은 [검증 요약](evidence/verification-summary.json)에 기록했습니다. 실제 Runtime 관찰 38건·Screenshot 42개·Source Hash 21개·실제 이미지 Hash 10개를 대조했고, 문서 링크와 관찰별 증거 파일 누락은 0건입니다. 순수 정책 Trace도 다시 실행해 원본 1표/CHS 4표 결과를 확인했습니다. 운영 Source가 바뀌지 않았으므로 이번 문서화를 위해 앱의 전체 테스트를 다시 실행하지 않았습니다.
