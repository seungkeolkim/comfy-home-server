# 해야 할 작업과 순서

> **후속 결정 갱신:** 사용자께서 전체 Ladder 정책은 StyleLab을 잘못 파악한 구현 오류이므로 폐기하고 원본을 따르도록 지시하셨습니다. 정책 선택을 다시 요청할 항목이 아닙니다. [부모 Selection 복원 명세](../style-lab-rebuild/stylelab_parent_selection.md)를 구현 기준으로 사용합니다. 이 문서의 Screenshot·수치는 수정 전 조사 기록이며, 후속 구현의 테스트 통과나 운영 반영을 증명하지 않습니다.

실제 조작 결과와 사용자 정정을 근거로 정리한 후속 작업입니다. 조사 단계에서는 앱 코드를 수정하지 않았으며, 아래의 구현 완료 조건은 조사 완료 조건과 구분합니다. 유지할 기능은 프로젝트 관리·다중 Prompt 비교, 제외할 초기 기능은 융합·다듬기입니다.

## 먼저 고칠 재현 결함

### P0 — Blind가 큰 보기에서 풀리는 문제

- 재현: Blind 켜기 → A/B 이름 숨김 확인 → 이미지 확대 → 실제 `세대001-조합02` 이름과 원본 링크의 파일 이름이 다시 보임.
- 대상: `web/style-preview/style-library.js`의 Viewer 열기·Polling 갱신, `style-comparison.js`의 Viewer 호출 맥락, 실제 Browser 테스트.
- 작업: Blind에서는 Viewer 제목·Alt·Tooltip에도 익명 정보를 사용합니다. Prompt 이름·순서·탐색·이미지 공간은 유지합니다. 원본 새 탭으로 이동할 때 파일 이름이 보이는 동작은 사용자가 Blind를 해제하는 동작과 구분해야 합니다.
- 완료 조건 제안: 같은 Pair에서 큰 보기·이전/다음·원본 전환·Polling·닫기/재열기 동안 일반 UI에 조합명·세대·Elo·성분이 노출되지 않음. Blind를 끄면 정상 정보가 복원되고 조합당 여러 Prompt 탐색도 유지됨.
- 근거: [실제 노출 Screenshot](evidence/chs-blind-viewer-identity-leak.png), [가리기 직전 화면](evidence/chs-audit-blind-mobile.png).

## 확정된 최소 Cycle 복원 작업

### P0 — 전체 Ladder 정책 폐기와 원본 부모 Selection 복원

- 원본 진화는 시작 시 상위 30% 부모를 고정해 최하위 부모부터 비교합니다. 조사 당시 CHS는 전체 기존 Pool의 위치까지 찾았습니다. 실제 1개 자녀의 패배 사례가 1표와 4표로 달랐고, 합성 동일 입력에서도 차이가 확인됐습니다.
- `full-ladder-placement-v2`와 이를 의도적 보강으로 보던 해석을 폐기합니다. 새 정책은 `stylelab-parent-selection-v1`이며, 원본의 1패 종료·tie 상향 확인·경계 Slot 자녀 대결·부모 기준 Elo를 복원합니다.
- 대상: `home_server/style_evolution_selection.py`, `style_evolution.py`, `style_voting_rules.py`와 선별 상태 표시·회귀 테스트. 미확정 `planned`/`active` Batch만 전환하며 non-parent Vote는 원본 기록을 보존하고 계산에서 제외합니다. Undo도 새 정책으로 재해석하고 확정된 이력·이미지는 변경하지 않습니다.
- 완료 조건: 실제 API가 만든 Batch와 기존 미확정 Batch 모두 원본 Golden 결과를 따름. 최하위 부모에게 1패한 자녀는 추가 대결 없이 끝나고 Elo는 해당 부모보다 240 낮음. 승격 경계 밖 동일 Slot 전체에 불필요한 Round-robin을 요구하지 않음. 프로젝트·다중 Prompt에서도 같은 정책을 적용함.

### P0 — 무작위 신규 조합 추가와 진화 생성의 명시적 분리

- 원본은 이미 평가한 Pool에 Random 신규 조합을 별도로 추가할 수 있습니다. CHS 주 화면은 Pool이 갖춰지면 같은 생성 버튼을 다음 진화로 전환합니다.
- 대상: `style-evolution.js`, `style-generation.js`, 생성·진화 API 진입점. `/candidate-generation-plans`를 제거하고 Random은 `/random-generation-plans`, 진화는 `/evolution-plans`를 명시적으로 호출합니다. 기존 성분 설정·중복 방지·다중 Prompt 계획을 재사용합니다.
- 일반 Random newcomer는 기존 전체 Ladder에 별도로 배치합니다. 원본처럼 rated 24개 미만에서 미배치 신규가 2개 이상이면 신규끼리 먼저 비교하며, 진행 중 Placement는 먼저 완료합니다. 진화 자녀를 이 흐름에 섞지 않습니다.
- 완료 조건: Pool 규모에 따라 생성 방식이 조용히 바뀌지 않음. rated 23개와 24개에서 원본의 fresh 비교 경계가 재현됨. 생성 계획과 실제 제출, 세대 확정과 다음 생성은 각각 분리된 상태로 유지됨.

### P0 계약 — 세대 번호·취소·퇴역 의미

- CHS의 마지막 확정 세대와 원본의 현재 평가/다음 생성 세대를 같은 `현재 N세대`로 읽지 않게 합니다. CHS의 `확정 N / 준비 N+1` 표시를 유지합니다.
- 원본 취소는 자녀·해당 선별 기록을 삭제합니다. CHS는 이미지·Job을 보존하고 취소 상태로 둡니다. 같은 이름으로 같은 데이터 효과를 약속하지 않게 문구와 정책을 맞춥니다. 이번 실행에서 원본의 최종 삭제는 실행하지 않았습니다.
- 원본의 북마크 보호는 퇴역 대상에도 영향을 줍니다. 해당 부가 기능을 후순위로 둘 수 있지만, 보호 상태가 있는 원본 Pool과 보호 기능 없는 CHS Pool의 퇴역 결과를 같다고 주장하면 안 됩니다.
- 완료 조건 제안: 확인창의 이미지·이력 보존/삭제 범위, 실제 상태, 재개·확정 후 Undo 경계가 일치함. 이미 분리된 확정·다음 생성 흐름을 다시 결합하지 않음.

## 유지하고 재검증할 확장·이미 반영된 동작

- 새 프로젝트 저장이 이미지를 자동 생성하지 않는 경계, 두 프로젝트의 독립 후보·세대·투표, 여러 Prompt의 같은 조합 비교와 Undo는 이번 실제 실행에서 확인했습니다.
- 확정과 다음 생성은 현재 운영 화면에서도 이미 분리돼 있습니다. 같은 문제를 다시 구현하는 작업은 필요하지 않습니다.
- 큰 보기의 Elo·폐기 제거, 남은 높이 활용, Desktop 원본/Mobile Cache 기본값과 Prompt 탐색은 실제로 동작했습니다. 이 공간을 다시 관리 Panel로 채우지 않습니다.
- 융합·다듬기·Fork·세대 복원·Ablation 등을 이번 최소 기능의 선행 작업으로 추가하지 않습니다. 원본 수렴 안내가 다듬기로 이어진다는 이유로 제외한 기능을 몰래 되넣지 않습니다.

현재 승인된 후속 작업은 **원본 부모 Selection 복원과 Random 생성 분리**입니다. Blind 결함·Gallery·선별 조작 UX는 별도 후속 항목으로 유지합니다. 변경 후 검증 결과와 운영 반영 상태는 실제 확인 뒤 기록하며, 이 조사의 과거 증거로 대신하지 않습니다.
